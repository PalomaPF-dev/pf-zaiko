# Paloma在庫

製造現場・倉庫向けの在庫管理システム（Palomaシリーズ 第8弾）。
QRラベルで商品とロケーションを管理し、入出庫・受払履歴・棚卸・出庫指示・安全在庫アラートを一元化します。

- **マスタ設定** — 商品マスタ（図番・品名・単位・ロットサイズ＋在庫管理キー・安全在庫）／**品目マスタ**（資材W/F の品目を事前登録。品目コードで呼び出して商品化）／ロケーション設定（`エリア-棚-段-間口` 例 `A-01-3-2`、自動採番・範囲一括生成）／取引先設定（仕入先・出荷先・移動先を1リストで種別選択、管理番号あり）
- **ラベル** — 商品ラベルは入庫・移動時に **現品票**（QR・商品CD・数量・仕入先/移動先）を都度印刷。ロケーションラベルはロケーション設定から各ロケ発行。**SATO のラベルプリンター**（実寸50×35mm）や A4/PDF に対応
- **入出庫** — カメラでQRスキャン → 入庫・出庫・調整・ロケ間移動。`stock` を正として受払を原子記録
- **出庫指示** — 出荷伝票（得意先・出荷グループ・明細→ロケ自動引当）→ ロケ順ピッキングリスト印刷 → **指示×ロケ×商品ラベルの3点照合**で誤出荷を防止して出庫
- **受払履歴** — 入荷・出荷・調整・移動・棚卸差異を時系列で照会・CSV出力
- **棚卸** — 指示（帳簿数スナップショット）→ 記入リスト印刷 → 実棚入力 → 差異確認 → 在庫反映
- **在庫アラート** — 安全在庫を下回った商品を毎日の Cron で検出しメール通知（Resend）

## 技術構成

- Next.js 16（App Router）+ Tailwind CSS 4 — 他のPalomaシリーズと同一パターン
- Neon Postgres（`DATABASE_URL`）/ next-auth（会社＋ユーザー、30日トライアル、使い捨てデモ）
- QR生成 `qrcode` / QRスキャン `html5-qrcode`
- Stripe サブスク / Resend（アラートメール）
- Capacitor リモート読込（iOS アプリ化用、`jp.paloma-pf.zaiko`）

## データモデル

`stock`（商品×ロケ×数量）を現在庫の正とし、`transactions`（受払）を追記専用の証跡ログとする二重管理。
入出庫は `sql.transaction([...])` で stock UPSERT と transactions INSERT を1バッチ原子実行するため不整合が起きない。

`item_master`（品目マスタ）は在庫を持たない参照カタログで、`products`（商品）とは別テーブル。
品目コード（＝W/F の図番9桁）で引き当てて商品を起こすと、そのコードが `products.drawing_no` に入り、
以降はスキャン・手入力・検索のいずれからも同じコードで呼び出せる。

## 品目マスタ（資材W/F）

資材ワークフロー（W/F）に登録済みの品目を **`src/data/item-master.json` に同梱** してあり、
マスタ設定 →「品目マスタ」を最初に開いたときに会社ごとの `item_master` へ自動で取り込まれる（冪等）。

- **呼び出し** — マスタ設定 →「品目マスタ」で **品目コード（`06-26105-00` / `062610500`）・品名・仕入先** から検索。
  商品登録フォーム冒頭の「品目コードから呼び出す」でも同じ引き当てができ、品名・図番・購入先・ロットサイズが入る。
- **商品化** — 「この品目で商品を登録」を押すと `/products/new?item=<品目コード>` が開き、品目コードが**図番**として登録される。
- **更新** — W/F から新しい品目マスタを受領したら、次のコマンドで同梱データを作り直してデプロイする。
  基準日（版）が変わると「品目マスタ」画面に取込ボタンが出る。

  ```bash
  pip install openpyxl
  python3 scripts/build-item-master.py 品目マスタ_20260807.xlsx
  ```

  1品目コード＝1行に畳んで出力する（W/F は単価改訂ごとに行が増えるため、基準日に有効な最新改訂を採用）。
- **単位コード** — W/F の単位コード表はエクスポートに含まれないため、推測で単位名を当てず**コードのまま表示**している。
  コード表を入手したら `src/lib/itemCode.ts` の `ITEM_UNIT_LABELS` に追記すれば、一覧と商品登録の初期値に反映される。

## 開発

```bash
npm install
npm run dev   # http://localhost:5184
```

### 環境変数（.env.local）

| 変数 | 用途 |
| --- | --- |
| `DATABASE_URL` | Neon Postgres（在庫専用DB） |
| `NEXTAUTH_SECRET` / `NEXTAUTH_URL` | next-auth |
| `RESEND_API_KEY` / `ALERT_MAIL_FROM` | 安全在庫アラートメール |
| `CRON_SECRET` | Cron 認証（/api/cron/stock-alert） |
| `STRIPE_SECRET_KEY` ほか | サブスク課金（シリーズ他アプリと同構成） |

## ラベル印刷（SATO ラベルプリンター）

商品の現品票（50×35mm）とロケーションラベルはブラウザの印刷ダイアログから発行します。
SATO のラベルプリンターを Windows ドライバで接続し、印刷ダイアログで **SATOプリンターと用紙（ラベルサイズ）を選択**、
**倍率100%（実寸）・余白なし**で印刷してください。A4プリンタなら「PDFとして保存」も可能です。
QRには在庫管理キーが入り、スキャンでその商品の在庫画面が開きます（出庫時の3点照合にも使用）。

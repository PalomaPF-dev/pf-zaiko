# Paloma在庫

製造現場・倉庫向けの在庫管理システム（Palomaシリーズ 第8弾）。
QRラベルで品目とロケーションを管理し、入出庫・受払履歴・棚卸・出庫指示・安全在庫アラートを一元化します。

- **マスタ設定** — 品目マスタ（図番・品名・単位・ロットサイズ＋在庫管理キー・安全在庫。**資材W/F 品目カタログ**から品目コードで呼び出して登録できる）／ロケーション設定（`エリア-棚-段-間口` 例 `A-01-3-2`、自動採番・範囲一括生成）／取引先設定（仕入先・出荷先・移動先を1リストで種別選択、管理番号あり）
- **ラベル** — 品目ラベルは入庫・移動時に **現品票**（QR・品目CD・数量・仕入先/移動先）を都度印刷。ロケーションラベルはロケーション設定から各ロケ発行。**SATO のラベルプリンター**（実寸50×35mm）や A4/PDF に対応
- **入出庫** — カメラでQRスキャン → 入庫・出庫・調整・ロケ間移動。`stock` を正として受払を原子記録
- **出庫指示** — 出荷伝票（得意先・出荷グループ・明細→ロケ自動引当）→ ロケ順ピッキングリスト印刷 → **指示×ロケ×品目ラベルの3点照合**で誤出荷を防止して出庫
- **受払履歴** — 入荷・出荷・調整・移動・棚卸差異を時系列で照会・CSV出力
- **棚卸** — 指示（帳簿数スナップショット）→ 記入リスト印刷 → 実棚入力 → 差異確認 → 在庫反映
- **在庫アラート** — 安全在庫を下回った品目を毎日の Cron で検出しメール通知（Resend）
- **権限** — 閲覧は管理者のみ全工場、入出庫は**所属工場のみ**（工場に所属しないポータル管理者は全工場で入出庫可）

## 技術構成

- Next.js 16（App Router）+ Tailwind CSS 4 — 他のPalomaシリーズと同一パターン
- Neon Postgres（`DATABASE_URL`）/ next-auth（会社＋ユーザー、30日トライアル）
- QR生成 `qrcode` / QRスキャン `html5-qrcode`
- Stripe サブスク / Resend（アラートメール）

## データモデル

`stock`（品目×ロケ×数量）を現在庫の正とし、`transactions`（受払）を追記専用の証跡ログとする二重管理。
入出庫は `sql.transaction([...])` で stock UPSERT と transactions INSERT を1バッチ原子実行するため不整合が起きない。

`item_master`（資材W/F 品目カタログ）は在庫を持たない参照専用テーブルで、`products`（品目マスタ）とは別物。
品目コード（＝W/F の図番9桁）で引き当てて品目マスタに登録すると、そのコードが `products.drawing_no` に入り、
以降はスキャン・手入力・検索のいずれからも同じコードで呼び出せる。

## 資材W/F 品目カタログ

資材ワークフロー（W/F）に登録済みの品目を **`src/data/item-master.json` に同梱** してあり、
マスタ設定 → 品目マスタ →「資材W/Fから探す」（`/items`）を最初に開いたときに、
会社ごとの `item_master` へ自動で取り込まれる（冪等）。

- **呼び出し** — `/items` で **品目コード（`06-26105-00` / `062610500`）・品名・仕入先** から検索。
  品目登録フォーム冒頭の「品目コードから呼び出す」でも同じ引き当てができ、品名・図番・購入先・ロットサイズが入る。
- **品目マスタへ登録** — 「品目マスタに登録」を押すと `/products/new?item=<品目コード>` が開き、品目コードが**図番**として登録される。
- **一括登録** — 一覧のチェックボックスで選んで「品目マスタに一括登録」（最大500件/回、登録済みは自動スキップ）。
  カタログには役務・費用系（保守・処理・運賃・弁当など約700件）が含まれるため全件登録はせず、
  **現物在庫を持つ品目だけ**を選んで登録する運用。ZK連番は既存の続きから一括採番される。
- **カタログの削除** — 在庫管理に不要な品目はチェックして「選択を削除」で一覧から外せる（品目詳細からも1件ずつ可）。
  実体は `hidden` フラグの非表示なので、**W/F 新版の取込でも復活せず**、「削除済み」フィルタからいつでも元に戻せる。
  削除済みの品目は検索・品目コード呼び出し・一括登録の対象から外れる。
- **品目マスタの削除** — 品目一覧（/products）のチェックボックスで一括削除、または品目編集画面から1件ずつ削除できる。
  **受払履歴（入荷・出庫などの記録）がある品目は証跡保護のため削除できない**（一括ではスキップ・単品では案内表示）。
  履歴のある品目は編集画面で「有効」を外して無効化する。
- **更新** — W/F から新しい品目マスタを受領したら、次のコマンドで同梱データを作り直してデプロイする。
  基準日（版）が変わると `/items` に取込ボタンが出る。

  ```bash
  pip install openpyxl
  python3 scripts/build-item-master.py 品目マスタ_20260807.xlsx
  ```

  1品目コード＝1行に畳んで出力する（W/F は単価改訂ごとに行が増えるため、基準日に有効な最新改訂を採用）。
- **単位コード** — W/F の単位コード表はエクスポートに含まれないため、推測で単位名を当てず**コードのまま表示**している。
  コード表を入手したら `src/lib/itemCode.ts` の `ITEM_UNIT_LABELS` に追記すれば、一覧と品目登録の初期値に反映される。

## 工場スコープ（閲覧と入出庫）

ポータルの部署が「工場」種別のとき `users.factory` に工場名が入り、`sites.name` と突合して工場を決める。
スコープは**閲覧**と**入出庫**で別（`src/lib/scope.ts`）。

| ユーザー | 閲覧 | 入出庫 |
| --- | --- | --- |
| 管理者（工場所属あり） | 全工場 | **所属工場のみ** |
| 一般・作業者（工場所属あり） | 所属工場のみ | 所属工場のみ |
| 工場に所属しない（ポータル管理者など） | 全工場 | 全工場 |

管理者は職場セレクタで他工場の職場も選べる（在庫台帳・受払履歴などを見るため）が、
その状態では入荷・入庫・出庫・移動・調整・棚卸のボタンが出ず、Server Action 側でも
`assert*Operable`（`src/lib/scope.ts`）が弾く。画面には `ViewOnlySiteNotice` で理由を出す。

## 開発

```bash
npm install
npm run dev   # http://localhost:5184
```

### 環境変数（.env.local）

| 変数 | 用途 |
| --- | --- |
| `DATABASE_URL` | Neon Postgres（在庫専用DB） |
| `NEXTAUTH_SECRET` / `NEXTAUTH_URL` | next-auth |
| `RESEND_API_KEY` / `ALERT_MAIL_FROM` | 安全在庫アラートメール |
| `CRON_SECRET` | Cron 認証（/api/cron/stock-alert） |
| `STRIPE_SECRET_KEY` ほか | サブスク課金（シリーズ他アプリと同構成） |

## ラベル印刷（SATO ラベルプリンター）

品目の現品票（50×35mm）とロケーションラベルはブラウザの印刷ダイアログから発行します。
SATO のラベルプリンターを Windows ドライバで接続し、印刷ダイアログで **SATOプリンターと用紙（ラベルサイズ）を選択**、
**倍率100%（実寸）・余白なし**で印刷してください。A4プリンタなら「PDFとして保存」も可能です。
QRには在庫管理キーが入り、スキャンでその品目の在庫画面が開きます（出庫時の3点照合にも使用）。
